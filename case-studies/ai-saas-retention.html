AI SaaS Retention & Competitive Intelligence Platform

An end-to-end analytics engineering platform that ingests 500K+ behavioral events into a layered PostgreSQL warehouse modeled with dbt Core, uncovering retention patterns across AI SaaS products and predicting long-term user churn.

GitHub Repo Contact
Business goal: understand why AI SaaS products lose 70% of users in month one, identify what separates long-term power users from churned ones, and surface competitive intelligence across product categories.

Problem

AI SaaS products face extreme early churn but lack visibility into which users will stick around and why. Without a structured warehouse and retention framework, product teams can't distinguish normal drop-off from fixable retention failures.

Approach

  • Ingested 500K+ Yelp behavioral events and Product Hunt API data into PostgreSQL
  • Built a layered warehouse (raw to staging to marts) with dbt Core
  • Created retention cohort and survival input fact tables
  • Ran Kaplan-Meier survival analysis to measure user longevity
  • Trained XGBoost churn prediction model on features from dbt marts
  • Implemented 31 automated dbt tests for data quality
  • Set up GitHub Actions CI/CD to run dbt build on every push

Results (high-level)

  • Discovered 70% month-1 churn rate across AI products
  • Found an 8x survival gap between Power Users and New Users
  • Identified review count and review frequency as strongest retention predictors
  • XGBoost model achieved 0.71 AUC-ROC for churn prediction
  • 31 automated dbt tests catch data quality issues before they reach dashboards

Tech Stack

  • dbt Core (warehouse modeling, testing)
  • PostgreSQL (data warehouse)
  • Python, Pandas, XGBoost
  • Kaplan-Meier survival analysis
  • GitHub Actions (CI/CD pipeline)
  • Streamlit (interactive dashboard)

Warehouse Architecture

  • Raw layer: Immutable ingestion of Yelp JSON and Product Hunt API data
  • Staging layer: Standardized transformations, type casting, deduplication
  • Marts layer: Business-facing tables for retention cohorts, survival inputs, and competitive intelligence

What Makes This Different

  • Not just a notebook: full warehouse + CI/CD + automated testing
  • Dashboard reads directly from marts tables, not CSVs
  • dbt build runs on every push, preventing bad data from reaching downstream
  • Combines analytics engineering rigor with product analytics insights
